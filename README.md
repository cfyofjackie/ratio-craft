# RatioCraft · 图片比例裁切

一个极快、极简、不损失额外画质的图片比例裁切工具。纯前端静态网页，无后端、无框架、无依赖，可直接部署到 GitHub Pages。

**所有图片处理均在本地浏览器完成，不会上传到任何服务器。**

## 功能

- **批量处理**：一次选择 / 拖拽 / 粘贴多张图片，显示在侧边栏（手机端为顶部缩略图条）；点哪张编辑哪张，每张图各自记住比例、缩放、位置、旋转，切走再切回原样恢复；缩略图带比例角标和已导出小勾，可单张删除
- **比例自动识别**：切入一张图时自动检测其宽高比并应用（4:3、3:4、3:2、2:3、16:9、9:16、1:1，误差 1% 内自动归拢；其他比例按精确值照实应用）；手动选择的比例永久优先于自动识别
- 预设比例：1:1、3:4、4:3、2:3、3:2、9:16；自定义比例（如 `6:9`，自动校验并化简为 2:3）
- 固定比例裁切框，图片在框内移动和缩放，始终覆盖裁切框、不露空白
- 鼠标拖动 + 滚轮缩放（以光标为锚点）；手机单指拖动 + 双指捏合缩放
- **精准倍数缩放**：输入倍数（如 `2` 放大两倍、`1.1` 放大 1.1 倍）回车即生效。绝对倍数语义——相对初始铺满状态，不与当前缩放累乘；以裁切框中心为锚点，上限 16 倍
- **井字格辅助线**：三等分构图线，默认开启，可一键开关（偏好记忆），仅预览层、绝不进入导出图
- 旋转 90°（只转图片，不改变所选比例和输出尺寸）；一键恢复默认位置和缩放
- 实时显示原图分辨率、当前输出分辨率和缩放倍数
- **窗口缩放不破坏构图**：浏览器窗口变大变小时，已选定的构图内容保持不动，导出结果与窗口大小无关
- 导出 JPG（quality 0.98，透明区域填白底）/ PNG（无损，保留透明）
- **全部导出**：一键按每张图各自的状态依次导出全部图片；**指定保存位置**（Chrome/Edge 桌面端可选定文件夹并记住授权，直接写入；其他浏览器回退默认下载）。文件名格式 `原文件名_比例_宽x高.扩展名`

## 拼图模式

裁切完成后点顶栏"拼图"进入，用**已裁好的成品**拼图：

- 模板：上下两张 / 左右两张 / 田字格 / 九宫格，格数固定；
- **画布比例自适应**：上下/左右每格保持原比例（两张 4:3 上下拼 → 整图 2:3，零裁切零留白）；田/九宫画布比例取全部选中图比例的平均值；
- 格子 cover 铺满、无留白；照片分辨率不足时自动放大补齐；
- 每格长边 1080px，格间距可调（0–40），导出前显示总输出尺寸；
- 自由位置：点选格子后点图库替换、拖拽两格互换；
- 整图导出 JPG/PNG，文件名 `collage_模板_宽x高.扩展名`。

## 画质承诺

**Preview resolution ≠ Export resolution**

- 导出画布始终按原图像素换算的尺寸创建，绝不截取低分辨率预览 Canvas；
- 不主动 resize、不做二次降采样、不压缩到固定尺寸；
- 原图 6000×4000，裁切后能保留多少原始像素就保留多少；
- 解码时应用 EXIF 方向，避免手机照片导出后横竖颠倒；
- 只有用户在预览里放大（画面放大 = 裁切范围变小 = 输出像素变少）才会减少输出像素，这是裁切的物理含义，不是工具在降画质。

## 本地运行

无任何构建步骤，两种方式任选：

```bash
# 方式一：直接用浏览器打开
双击 index.html

# 方式二：起一个静态服务器（推荐，行为与线上完全一致）
python -m http.server 8000
# 或
npx serve .
# 然后访问 http://localhost:8000
```

## 部署到 GitHub Pages

1. 推送到 GitHub 仓库（如 `cfyofjackie/ratio-craft`）；
2. 仓库 **Settings → Pages**；
3. Source 选 **Deploy from a branch**，分支选 `main`，目录选 `/ (root)`，保存；
4. 稍等一两分钟，访问 `https://<用户名>.github.io/ratio-craft/`。

## 项目结构

```text
/
├─ index.html          # 页面骨架
├─ css/
│  └─ style.css        # 样式（浅色、响应式）
├─ js/
│  ├─ crop-engine.js   # 裁切核心状态机（纯逻辑，零 DOM 依赖）
│  ├─ image-utils.js   # 图片加载 / 变换绘制 / 导出 / 比例解析
│  └─ app.js           # 页面交互层（事件、流程编排）
└─ README.md
```

### 核心设计

- **crop-engine.js 是纯 JS 状态机**：输入图片尺寸、比例、旋转、位移、缩放，输出预览渲染参数与按原图像素换算的导出参数（`getExportParams()`）。不碰任何 DOM 和浏览器 API，预览与导出共用同一套变换数学，保证所见即所得。
- **导出流程**：`getExportParams()` → 按 `width × height`（原图像素级）创建离屏 Canvas → JPG 先铺白底 → `toBlob('image/jpeg', 0.98)` 或 `toBlob('image/png')` → 触发下载。
- **超大图兜底**：移动端浏览器单画布约 1600 万像素上限（iOS Safari），超出会导致导出静默失败。工具在信息栏实时预警，导出前检查并给出明确报错，而不是没反应。
- 已确认的交互决策（切换比例重置视图、旋转语义、自定义比例规则等）记录在 `图片比例裁切工具开发 Prompt.md` 的"实现决策"一节。

## 迁移到小红书小程序时可复用的模块

| 模块 | 复用情况 |
| --- | --- |
| `js/crop-engine.js` | **100% 原样复用**。纯 JS，无任何浏览器 API 依赖，直接拷进小程序项目 |
| `js/image-utils.js` 中的 `parseRatioInput` / `simplifyRatio` / `canvasLimit` | 原样复用 |
| `js/image-utils.js` 中的 `drawSource` / `exportImage` | 变换数学相同，但需把 Canvas 调用替换为小程序 `canvas` API |
| `js/app.js`、`css/`、`index.html` | UI 层，需用小程序页面重写，但交互逻辑（Pointer Events 的拖动 / 双指缩放状态机）可作为参考 |
